# 按知识类型组织笔记

以下结构是把学习研究转化为可用笔记的设计选择，并非被实验确认的唯一最优模板。以材料的知识关系、读者基础和学习任务为准，短资料可以合并层级。

## 通用骨架

```markdown
# 资料或主题名称

来源、版本、笔记更新日期；学习范围与必要前置。

## 整体框架
资料回答什么问题，主要概念如何关联，读完应该能解释或完成什么。

## 按知识依赖展开的正文
标题使用实际知识名称，各节采用合适的内部结构，来源就近标注。

## 闭卷自测
题目先出现，答案在独立区块。无需重新复制一遍正文。

## 答案与定位
判分要点、条件、正文位置；也可用折叠块。

## 待澄清与范围边界
仅在存在实际缺口时保留。
```

复习用法可以在自测开头写一两句，不必另造一章流程说明。参考手册或纯归档请求可不含自测。已有目录和格式优先。

## 选择结构

| 知识类型 | 建议组织 | 必须保留的关系 |
| --- | --- | --- |
| 概念/分类 | 定义 → 特征与边界 → 相邻概念对比 → 正例与反例 | 属于什么、不同在哪、什么情形不成立 |
| 原理/机制 | 问题 → 前提 → 因果/推导链 → 预测 → 适用边界 | 每一步如何由前一步得到，何时失效 |
| 操作/工具 | 目标 → 前置与输入 → 关键步骤 → 输出验证 → 排错 | 操作次序、参数意义、成功与失败判断 |
| 数学/算法 | 问题 → 符号与假设 → 推导/算法 → 例题 → 边界/复杂度 | 符号含义、不变量、步骤依据和适用条件 |
| 研究/论证 | 问题 → 主张 → 方法与证据 → 反驳/限制 → 可支持结论 | 作者说了什么、证据实际支持到哪里 |
| API/参考 | 功能分组 → 契约 → 输入/输出 → 用例 → 错误与版本差异 | 同名概念差异、默认值、互斥条件 |
| 历史/叙事 | 时间/因果线 → 关键事件 → 多方解释 → 证据与争议 | 时间顺序、因果与事后解释的区别 |

不要把只有定义的资料硬补成操作指南；不要把理论推导压成“结论＋一句用法”。用户要实操时，操作与验证优先；用户要理解时，机制和关系优先，覆盖范围不因此暗中缩小。

## 层次与例子

- 先用简短概览建立整体关系，再展开知识单元。前置只写理解本资料真正需要的内容，不重新写一本教材。
- 同一小节容纳一个连贯模型或操作，而非强制一概念一页。概念之间的“依赖、导致、对比、组成”用文字、表格或有标注的图表达。
- 一个例题需要保留题设、条件、关键解题步骤与依据、结果及检查。随后可给一题改变条件的练习，检查能否选用知识；尚无基础的读者先有解释与例题，再做开放练习。
- 对反例说明违反了哪个条件。对作者故事，仅删去与证据无关的叙事；若故事提供反证、数据来源或历史因果线，就保留相关事实。
- 相关的图与解释放一起，图注说明图中可见的关系和原来源。图承担关系表达，正文承担条件与证据，二者相互补足。

## 自测与反馈

按目标选择题型，不必强制凑齐：

- **回忆**：不给定义提示，要求用自己的话说明概念及其必要条件。
- **辨析**：比较容易混淆的概念，要求说出决定差异的条件。
- **解释**：为什么会得到这个结论？某一步依赖哪条前提？
- **应用**：给一个可由资料解决的新情境，要求选方法、执行并验证。
- **边界**：改变一个条件后结论还成立吗？指出依据。
- **重建**：遮住正文，重画关系或重写步骤，再对照纠错。

先作答，再看答案。答案给关键要点、适用条件和正文定位，不要求逐字背诵。自动生成的题目要检查：题干是否泄漏答案、是否有歧义、正确答案是否唯一（开放题则明确评分维度）、是否需要资料未教过的知识。

复习把成功、部分、失败落实到实际作答：失败时回到相应正文纠错，较早重试；成功后在更晚一次学习中再提取，并适当改变情境。调整间隔与难度是实践建议，不是假称为研究给出的精确算法。
